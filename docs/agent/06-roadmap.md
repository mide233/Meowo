# 06 · 路线图

- 状态：Baseline
- 版本：v0.1.0
- 最后更新：2026-10-19
- 说明：本路线图按“可验证的阶段”组织，不承诺日历日期。每个阶段完成后由项目负责人检查退出标准，再进入下一阶段。

---

## 1. 路线图原则

1. **先降低致命风险**：许可证、笔输入、渲染性能、文件格式、图书引擎必须在写大量业务代码前验证。
2. **每个阶段都可运行、可测试**：不长期维护不能启动的半成品分支。
3. **数据安全先于功能数量**：持久化、恢复、锁与格式不变量在 Phase 1 建立。
4. **按垂直切片交付**：每个功能从数据模型、FFI、UI 到测试完整打通，再扩展。
5. **不静默缩减范围**：若阶段范围需要调整，更新需求与决策文档并获得确认。
6. **性能是持续门槛**：从 Phase 2 起每阶段保留基准，不把性能留到最后。
7. **OQ 阻塞相关阶段**：未关闭的许可证/范围问题不得用临时私有依赖绕过。

阶段编号与 `01-functional-requirements.md` 的 `Phase` 列一致。

---

## 2. 阶段总览

| 阶段 | 目标 | 主要产出 | 退出标志 |
|---|---|---|---|
| Phase 0 | 技术可行性与工程基础 | 仓库、构建、CI、核心架构骨架、高风险验证报告 | 所有关键 spike 有结论，许可证/EPUB 路线确认 |
| Phase 1 | 可用的本地文档底座 | 资料库、创建/打开/保存、无限与书页骨架、页面/图层基础、恢复 | 离线创建/保存/重开稳定，格式与迁移测试通过 |
| Phase 2 | 笔迹核心 | 笔、荧光笔、压感、整笔擦除、画布导航 | 真实笔设备可完成书写闭环，延迟达标 |
| Phase 3 | 混合内容工作区 | 文本/Markdown/LaTeX、图片、附件、完整图层、搜索 | 混合文档端到端可用，搜索与删除保护正确 |
| Phase 4 | 喵书籍 | PDF 导入/渲染/批注；EPUB 按决策交付 | 图书打开、翻页、批注、重开稳定 |
| Phase 5 | 发布硬化 | 性能、无障碍、国际化、导出、打包、完整验收 | 1.0 发布清单全部通过 |

## 3. Phase 0 · 基础与高风险验证

详细任务见 [plans/phase-0-foundation-and-spikes.md](plans/phase-0-foundation-and-spikes.md)。本阶段只建立必要骨架和验证，不追求产品功能。

### 3.1 目标

- 建立可重复的 Flutter + C++23 + FFI 工程骨架；
- 在 Linux、Windows、Android 上完成最小构建与测试闭环；
- 验证笔输入、渲染性能、SQLite 格式、PDF/EPUB 引擎四条高风险路线；
- 关闭或明确升级 OQ-001（许可证/EPUB）、OQ-002（MD 阅读范围）；
- 建立文档、计划、报告、CI 的工作纪律。

### 3.2 工作项

1. 仓库初始化、目录结构、许可证占位（待 OQ-001）、`.gitignore`、编辑器配置；
2. Flutter 应用壳 + Material 3 主题骨架；
3. `meowo_core` FFI 插件：CMake、C++23、C ABI、ffigen、Dart 调用 smoke；
4. GoogleTest/CTest 与 Dart 测试、基础 CI；
5. 输入/笔压 spike：Android 笔、Windows 触控笔、Linux 可用输入设备；
6. 渲染/笔迹性能 spike：10k–20k 笔迹、平移/缩放、延迟测量方法；
7. SQLite 格式 spike：schema、WAL、事务、崩溃恢复、迁移样例；
8. PDFium 集成 spike；EPUB 引擎许可证与能力评估；
9. 品牌/主题令牌占位与测试字体策略；
10. CI 基线：Linux 单元 + 格式 + 构建，Windows 构建，Android 构建。

### 3.3 退出标准

- [ ] 三个平台均可构建并启动最小应用；
- [ ] Dart → C ABI → C++ → 返回数据的 smoke 测试通过；
- [ ] C++ 单元测试与 Dart 测试在 CI 运行；
- [ ] 至少一台真实 Android 笔设备完成压感/掌拒/延迟记录；
- [ ] 20k 笔迹场景有可复现基准与结论；
- [ ] `.meowo` 最小 schema 可创建、保存、重开、迁移、恢复；
- [ ] PDFium 最小渲染 demo 可运行并记录许可证/体积；
- [ ] EPUB 路线有书面结论（采用/延期/购买/自研），并更新 OQ-001；
- [ ] 关键架构决策无未记录的偏离；
- [ ] Phase 1 计划已按验证结果修订。

### 3.4 明确不做

- 完整编辑器 UI、完整资料库、账号/同步；
- 正式发布包、商店素材；
- 未确认许可证的 EPUB 引擎进入发布二进制；
- 大规模功能开发。

## 4. Phase 1 · 本地文档底座

### 4.1 目标

用户可以在离线状态下创建无限或书页文档，进行基础页面/图层操作，可靠保存并重新打开。

### 4.2 范围（对应需求）

- 应用启动、资料库初始化、空状态（`APP-001`、`APP-003`、`APP-005`）；
- 资料库列表、打开、重命名、删除/回收站基础（`LIB-001`–`LIB-003`、`LIB-005`、`LIB-007`、`LIB-010`、`LIB-012`、`LIB-013`）；
- 新建无限/书页文档、纸张尺寸选择与不可变约束（`DOC-001`–`DOC-003`、`DOC-007`、`DOC-008`、`DOC-010`–`DOC-012`）；
- 文档打开/关闭/锁/只读（`DAT-001`–`DAT-006`、`DAT-008`、`DAT-009`、`DAT-012`、`DAT-014`、`DAT-015`）；
- 自动保存、保存状态、崩溃恢复、备份（`DAT-003`、`DAT-004`；`NFR-004`）；
- 页面模型与基础页面导航（书页单页视图、缩略图占位）；
- 图层数据模型与基础面板（创建/排序/可见/锁定/激活；完整文本/图片图层行为在 Phase 3）；
- 最小画布显示：纸张背景、空白页、缩放/平移占位；
- 搜索入口占位（真实文本搜索在 Phase 3）；
- 设置存储骨架、主题、语言骨架；
- 格式不变量、迁移、损坏恢复测试。

### 4.3 退出标准

- [ ] 断网首次启动可创建文档；
- [ ] 无限与书页文档均可保存、关闭、重开，页面/图层结构不丢失；
- [ ] 保存状态真实反映结果，失败可重试且不假装成功；
- [ ] 强杀后可恢复到最近一次成功保存；
- [ ] 损坏/未来版本/只读文件有明确处理；
- [ ] 同一文档在 Linux/Windows/Android 可打开（无笔迹阶段检查结构）；
- [ ] schema v1、迁移样例、格式测试通过；
- [ ] 资料库搜索/排序/收藏/回收站基础可用；
- [ ] Phase 2 的输入/渲染接口已冻结到可实施程度。

### 4.4 风险关注

- 文件锁与多实例；
- Android SAF 与工作区路径；
- 自动保存与撤销/事务边界；
- 页面/图层模型的早期抽象是否足够承载笔迹和图书背景。

## 5. Phase 2 · 笔迹核心

### 5.1 目标

在真实触控笔设备上完成“打开文档 → 书写/高亮 → 整笔擦除 → 撤销 → 保存 → 重开”的稳定闭环，并达到延迟目标；为 Phase 3 的选择与像素擦除保留几何/撤销接口。

### 5.2 范围

- 笔迹采集、压感、平滑、颜色/粗细、钢笔与荧光笔（`INK-001`–`INK-004`、`INK-007`、`INK-008`、`INK-011`、`INK-012`）；
- 无限画布与书页画布的绘制、相机、缩放/平移、单页视图（`CAN-001`–`CAN-004`、`CAN-006`–`CAN-009`）；
- 整笔擦除、可调擦除尺寸、隐藏/锁定图层保护（`SEL-001`、`SEL-003` 的 Phase 2 部分）；
- 撤销/重做基础（画布操作；按 D-012 分层，完整选择撤销在 Phase 3）；
- 输入策略与掌拒（`INP-001`–`INP-004`、`INP-010`）；
- 笔迹持久化/重开一致性、性能基准与真实设备矩阵；
- 手势与工具切换、快捷键基础；
- 为 Phase 3 的像素擦除/选择预留几何与命令接口，不提前实现完整选择 UI。

### 5.3 退出标准

- [ ] Android 平板真实笔：压感、掌拒、快速/慢速书写可用；
- [ ] Windows 触控笔二合一完成同等验收；Linux 至少鼠标/触控板绘制可用；
- [ ] 笔尖到显示 P95 在参考设备达到 < 50 ms（记录方法/设备）；
- [ ] 20k 笔迹/页可打开、导航、继续绘制，无崩溃；
- [ ] 整笔擦除、擦除尺寸、隐藏/锁定图层保护与撤销/重做行为符合规范；像素擦除和完整选择在 Phase 3 验收；
- [ ] 笔迹在保存/重开后几何与压力一致；
- [ ] 书页文档单页视图与翻页/缩略图导航稳定；
- [ ] 输入冲突（双指、掌、笔）有自动化逻辑测试与手工记录；
- [ ] 性能报告与已知限制归档。

### 5.4 风险关注

- Flutter 各平台压感/预测事件差异；
- 高刷新率与帧调度；
- 后续 Phase 3 的像素擦除切分与撤销内存（本阶段只保留接口）；
- 后续选择/变换的坐标精度与大文档命中性能（本阶段不实现完整选择）。

## 6. Phase 3 · 文本、图片、附件与混合内容

### 6.1 目标

把画布从“手写纸”升级为完整笔记工作区：文本/公式、图片编辑、附件、完整图层、搜索与跨页对象操作。

### 6.2 范围

- Markdown/GFM/LaTeX 解析、渲染、源码/预览、链接、安全清洗（`TXT-001`–`TXT-016`，受 OQ-003 约束）；
- 文本框、本底文本、自动高度/固定高度溢出、字体/对齐/颜色（`TXT-003`–`TXT-014`，受 OQ-004 约束）；
- 文本局部撤销与提交为全局撤销单元（`TXT-015`、D-012）；
- 图片导入、变换、裁剪/旋转/翻转、透明度、格式校验（`IMG-001`–`IMG-010`）；
- 附件导入、图标/链接、文件夹、引用删除保护（`ATT-001`–`ATT-011`）；
- 完整图层：重命名、透明度、跨层选择规则、锁定/可见（`LYR-001`–`LYR-007`、`LYR-009`、`LYR-010`）；
- 对象复制/粘贴/缩放、跨页粘贴（同一文档）、文本系统剪贴板（`SEL-002`、`SEL-004`–`SEL-008`、`SEL-010`、`SEL-011`、D-017）；
- 全文搜索标题+文本、结果定位（`LIB-006`、`LIB-011`、`CAN-011`）；
- 书页本底文本与上一页内容复用（复制/移动，不做自动续排）；
- 设置中的输入/工具偏好（`SET-002`）；
- 混合内容格式/迁移/性能测试。

### 6.3 退出标准

- [ ] Markdown/公式渲染与源码编辑稳定，恶意/畸形输入不执行脚本；
- [ ] 文本框/本底文本在无限/书页均可用，溢出行为符合 OQ-004；
- [ ] 图片裁剪/旋转变换保存重开一致；
- [ ] 附件可打开文件夹，被引用资产不能误删；
- [ ] 图层顺序/可见/锁定/跨层选择符合规范；
- [ ] 选择、复制、跨页粘贴、撤销完整；
- [ ] 搜索只返回标题/文本命中，点击定位正确，不误报手写；
- [ ] 文本输入在 Android IME、Windows/Linux 输入法下可用；
- [ ] 混合文档性能与内存达标；
- [ ] 无障碍与本地化检查进入常规流程。

### 6.4 风险关注

- Markdown/KaTeX 排版与编辑性能；
- 文本光标/IME/预览同步；
- 图片大资产与内存峰值；
- 附件路径/安全与删除引用；
- 搜索索引与文档事务的一致性。

## 7. Phase 4 · 喵书籍（PDF/EPUB）

### 7.1 进入条件

- OQ-001 已关闭并记录许可证结论；
- 若选择 AGPL/商业方案，已完成法律/分发影响确认；
- EPUB 若延期，必须明确更新 1.0 范围和需求，不得假装完成。

### 7.2 范围

- 图书导入入口、格式探测、导入设置（`BOOK-001`–`BOOK-004`、`LIB-004`、`DOC-009`）；
- PDF 引擎适配、页数/尺寸/目录、按页渲染（`BOOK-005`–`BOOK-009`）；
- 图书页只读背景、页面结构不可编辑（`BOOK-006`、`BOOK-014`、D-007）；
- 批注元素、图层、保存/重开、页面位置稳定（`BOOK-010`–`BOOK-012`）；
- 导入失败/损坏/密码/DRM 错误（`BOOK-015`、`BOOK-016`）；
- 图书页缓存、内存回收、首屏优先（`NFR-003`）；
- EPUB：按 OQ-001 结论实现固定分页快照 + 批注；保留原始 EPUB（若支持）；
- 图书性能、安全隔离、fuzz、跨平台一致测试。

### 7.3 退出标准

- [ ] PDF 导入后可翻页、跳转、缩放、批注、保存、重开；
- [ ] 批注锚点不因重开/窗口大小变化而漂移；
- [ ] 损坏/加密/超大文件有明确错误，不崩溃；
- [ ] 图书页结构不可增删/重排，UI 不提供误导入口；
- [ ] EPUB 按已确认范围交付或有正式范围变更记录；
- [ ] 图书引擎在超时/畸形输入下可隔离终止；
- [ ] 大型 PDF 首屏与翻页性能达标；
- [ ] 许可证/第三方声明完成。

### 7.4 风险关注

- EPUB 固定分页与标注漂移；
- PDFium 安全更新/构建体积；
- 图书页面缓存与内存；
- Android 大文件导入与存储权限。

- [ ] 性能/内存/包体达到目标或有批准例外；
- [ ] 无障碍与中英文验收通过；

- [ ] 项目负责人签署 1.0 范围冻结。

## 9. 依赖与关键路径

```text
Phase 0
  ├─ 构建/FFI/CI ───────────────┐
  ├─ 输入/笔压 spike ───────────┤
  ├─ 渲染/性能 spike ───────────┤
  ├─ SQLite/格式 spike ─────────┤
  └─ 图书引擎/许可证 ───────┐   │
                             │   ▼
Phase 1 文档底座 ◄───────────┘ (格式/存储)
      │
      ▼
Phase 2 笔迹核心 ◄─────────── 输入/渲染 spike
      │
      ▼
Phase 3 文本/图片/附件/搜索
      │
      ├──────────────► Phase 4 图书（受 OQ-001 约束）
      │                     │
      └─────────┬───────────┘
                ▼
           Phase 5 发布
```

关键路径：格式/持久化 → 笔迹 → 混合内容 → 图书 → 硬化。EPUB 许可证是 Phase 4 的强制门禁；笔输入与渲染风险是 Phase 2 的强制门禁。

## 11. 发布门槛（1.0）

1. 范围：用户确认 1.0 范围与所有 OQ 的最终结论；
2. 功能：所有 MUST 需求完成，SHOULD 未完成项有记录与批准；
3. 数据：格式 v1 冻结，迁移与恢复测试通过；
4. 性能：参考设备达标或有批准例外；
5. 质量：无 S0/S1，测试矩阵与手工矩阵通过；
6. 安全：许可证/依赖/隐私审查通过；
7. 体验：中英文、无障碍、视觉一致性验收；
8. 分发：三平台安装包、签名、说明、支持渠道就绪。

## 13. 路线图维护

- 每个阶段开始前，在 `docs/agent/plans/` 建立阶段计划，拆分可验收任务。
- 阶段中每周/每次里程碑更新计划状态与实际偏差。

- 本文件只描述阶段级路线；任务细节以对应计划为准。
