# 00 · 产品章程（Product Charter）

- 状态：Baseline / 待负责人确认范围细节
- 版本：v0.1.0
- 最后更新：2026-10-19

---

## 1. 一句话定义

**Meowo（喵记）是一款以手写和混合内容为核心的本地优先笔记软件，同时能够阅读并批注 PDF、EPUB 与 Markdown 内容。**

它不是“把网页编辑器搬到平板上”的工具，而是围绕 **笔、纸、书、思考痕迹** 构建的跨平台工作空间。

## 2. 产品愿景

让用户在 Android 平板/手机、Windows 与 Linux 设备上，以接近纸笔的直觉完成三件事：

1. **快速记下**：打开即写，压感手写、批注、贴图、加文本，不被工具打断。
2. **自由组织**：在同一文档中混合无限画布、固定书页、图层、文本和附件。
3. **读中记**：把 PDF/EPUB 变成可批注的书页，笔记与阅读内容处于同一空间。

## 3. 产品定位

| 维度 | 定位 |
|---|---|
| 类型 | 笔记 + 随手记 + 文档阅读/批注 |
| 核心输入 | 主动：手写笔、触控笔；辅助：键盘、鼠标、手指 |
| 文档模型 | 无极画布与固定书页双模型；PDF/EPUB 以固定书页背景呈现 |
| 数据策略 | 本地优先、单文件可携带、无需账号即可完整使用 |
| 设计语言 | Material Design 3，自适应布局，克制而有辨识度的“猫”品牌感 |
| 目标平台 | Android（手机/平板）、Windows、Linux（桌面/平板） |
| 技术栈 | Flutter UI + C++23 核心 + Dart FFI + SQLite |

## 4. 目标用户与核心场景

### 4.1 主要用户

- **学生与研究者**：在讲义、教材、论文 PDF 上做批注，同时手写推导和整理笔记。
- **设计师与工程师**：用无限画布画草图、贴参考图、写 Markdown 技术笔记。
- **阅读型用户**：在平板上阅读 EPUB/PDF，用笔做标注、摘录和关联笔记。
- **桌面笔记用户**：在 Windows/Linux 上使用数位板或触屏，也需要键盘文本与附件管理。

### 4.2 典型工作流

1. **随手记**：启动 → 新建无极喵文档 → 直接落笔 → 圈选、移动、补一张图片 → 自动保存。
2. **课堂/会议**：新建书页喵文档（A4 横向）→ 手写 + 文本框 → 插入附件 → 导出文档副本备份。
3. **精读**：导入 PDF → 生成喵书籍 → 在任意页用荧光笔和笔迹批注 → 新建独立笔记页记录摘要。
4. **资料整理**：资料库搜索 → 收藏 → 打开最近文档 → 管理附件文件夹。
5. **跨设备携带**：将 `.meowo` 文件复制到另一台设备打开，内容与附件完整保留。

## 5. 产品原则

### P1. 落笔优先（Pen-first）

- 进入文档到可书写不超过一次意图明确的点击。
- 笔迹延迟、断触、误触是同等级于崩溃的缺陷。
- 常用笔刷、颜色、粗细、橡皮与撤销必须在一层操作内可达。
- 不要求用户先选择“模式”才能开始写字；默认工具应合理。
- 任何非绘制 UI 都不得抢占笔的落点或遮挡大面积画布。

### P2. 本地优先与内容所有权（Local-first & Ownership）

- 不注册账号、不联网也能使用全部 1.0 功能。
- 单篇文档必须自包含：标题、页面、笔迹、图片、文本、附件、图层和图书源都在同一个 `.meowo` 文件中。
- 用户应能通过文件复制、导出快照完成完整备份，不依赖私有云。
- 文件格式必须有版本、迁移和拒绝损坏输入的明确行为。

### P3. 一个空间，多种内容（Mixed Canvas）

- 手写、文本、图片、附件、图层不是独立模块，而是同一画布上的一等元素。
- 用户可以在一次思维流中自由切换输入方式，不弹到另一个“编辑器应用”。
- 元素的选择、移动、缩放、删除、复制、撤销语义保持一致。

### P4. 阅读也是书写（Reading as Writing）

- 图书页是底层只读背景，批注和笔记叠加其上，不破坏原文件。
- 图书页的大小、分页和内容必须稳定可复现，关闭再打开不能发生标注错位。

### P5. 简洁但不简陋（Quiet UI）

- 默认界面只呈现当前任务必需的工具；高级功能通过面板、抽屉或上下文工具条出现。
- 视觉层级清晰，纸张是主角，UI 不喧宾夺主。
- 遵循 Material 3 的组件与状态语义，不做无法维护的“仿制皮肤”。
- “猫”元素克制、温暖、有品牌识别度，不幼稚化、不干扰专业使用。

### P6. 性能与可靠性是功能（Performance is a feature）

- 手写输入到屏幕反馈、页面打开、缩放平移、导入与保存都必须有明确性能预算。
- 任何用户操作不得导致不可恢复的数据丢失。
- 支持崩溃恢复、原子导入、失败回滚和可诊断错误。

### P7. 可访问与可维护（Accessible & Maintainable）

- 键盘、屏幕阅读器、文本缩放、对比度与减少动态效果从第一天纳入设计。
- 核心逻辑必须能在无 UI 的情况下单元测试。
- 不为短期进度引入无法替换的高耦合依赖。

## 6. 平台范围

### 6.1 1.0 支持范围

| 平台 | 形态 | 要求 |
|---|---|---|
| Android | 手机、平板 | 完整功能；手写笔/触控；自适应布局；系统分享/文件选择；最低版本由 Phase 0 决策 |
| Windows | 桌面、平板/二合一 | 完整功能；WM_POINTER 笔输入；触控与鼠标；高 DPI；文件拖放 |
| Linux | 桌面、平板 | 完整功能；Wayland/X11；笔输入按桌面环境能力降级；文件拖放 |

> Linux 触控笔在部分桌面环境/Flutter 版本上可能无法通过标准 PointerEvent 提供完整压感。Phase 0 必须验证并记录各平台输入能力。详见 [10-risk-register.md](10-risk-register.md)。

### 6.2 暂不支持但架构不排斥

- iOS、iPadOS、macOS；
- Web；
- 多窗口同时编辑同一文档；
- 后台云同步、实时协作。

这些平台/能力不进入 1.0 验收，也不得在文档中暗示已支持。

## 7. 产品成功标准

以下标准不是营销指标，而是 1.0 的工程与体验门槛：

1. 用户能在三平台创建、书写、插入图片/文本/附件、关闭并重新打开文档，内容完整无丢失。
2. 手写笔压感生效，笔迹以矢量保存；擦除后仍可无损缩放，不变成位图。
3. 两个文档类型、两种文本布局、任意页面的图层、PDF/EPUB 批注均可完成端到端使用。
4. 典型手写文档在目标设备上达到可接受的输入延迟和帧率（见性能预算）。
5. 强制终止应用后重新打开，已确认的编辑不丢失；正在进行的单笔最多丢失当前笔画。
6. 所有 1.0 MUST 需求均有需求 ID、测试或人工验收记录。
7. 中文/英文 UI 完整；核心流程可通过键盘完成；屏幕阅读器能访问文本与主要控件。
8. CI 在三个目标平台构建成功；核心 C++ 与 Dart 测试稳定通过。

## 8. 1.0 范围

### 8.1 必须交付

- 资料库：创建、打开、重命名、收藏、搜索、排序、回收站。
- 无极喵文档与书页喵文档。
- 书页纸张大小选择、页面增删/重排。
- 完整手写：压感、矢量笔迹、颜色/粗细、荧光笔、笔刷预设、压力曲线、描边擦除、像素擦除、套索选择/移动/复制/缩放/删除。
- 图层：增删、重命名、排序、显隐、锁定、透明度、元素归属。
- 图片：导入、移动/缩放/旋转、内置裁切编辑。
- 文本：CommonMark + GFM 子集 + LaTeX 数学、文本框、画布本底文本、编辑/预览。
- 附件：内嵌存储、画布图标、Markdown 链接、附件文件夹视图。
- PDF 导入与喵书籍批注；EPUB 导入与分页阅读（引擎路线待决策）。
- 自动保存、崩溃恢复、文档副本导出/备份。
- 全面单元测试、集成测试、性能基准与三平台构建。
- 中/英本地化、深色模式、键盘操作与基础无障碍。

### 8.2 明确不做（1.0）

- 账号、云同步、实时协作、多人共享链接。
- 手写 OCR、手写转文字、语音转写、AI 摘要/问答。
- 编辑 PDF/EPUB 原始内容，或移除 DRM。
- PDF 文本选择与文本重排（阅读渲染 + 批注为准）。
- 手写形状识别、公式手写识别、笔迹美化。
- 多窗口同时编辑同一文档。
- 无限画布与书页文档互相转换。
- 嵌套文件夹、标签体系、模板市场、插件系统。
- iOS/macOS/Web 正式支持。
- 将原生文档导出为 Word、Notion 等第三方私有格式。

### 8.3 1.0 之后候选

按用户价值排序，不构成承诺：

- 连续纵向翻页、双页视图；
- 文档标签/文件夹；
- PDF/PNG 导出；
- 自动备份与版本历史；
- 跨设备同步与冲突合并；
- 手写识别、搜索手写；
- 音频录制与时间轴；
- 更多纸张模板与封面；
- 形状/公式识别；
- iOS/macOS。

## 9. 核心术语与不变量

### 9.1 术语

- **喵文档**：一篇文档，一个 `.meowo` 文件。类型在创建时确定，1.0 不支持转换。
- **无极喵文档**：只有一个逻辑无限画布，没有固定页面边界。
- **书页喵文档**：固定纸张尺寸的多页文档，至少一页。
- **喵书籍**：由 PDF/EPUB 导入生成的书页喵文档，底层为只读图书页背景，页面结构跟随源文件。
- **元素**：墨迹、图片、文本、附件图标等可选中对象，必须归属于一个图层。
- **画布本底文本**：占据页面正文区域（或无限画布中的固定宽度文本栏）的特殊文本元素，仍属于图层。
- **图书页背景**：PDF/EPUB 渲染的只读内容，位于全部图层之下，不是普通元素。
- **图层**：每个书页/画布独立的一组有序元素；不跨页共享。
- **笔刷预设**：颜色、基础宽度、透明度、混合模式、压力曲线等可复用设置的集合。

### 9.2 不变量

1. 一个 `.meowo` 文件只包含一篇文档。
2. 无极文档恰好有一个逻辑画布；书页文档至少有一页；喵书籍的源页面不能删除或重排。
3. 所有可编辑元素必须位于某个图层；图书页背景和纸张背景不在图层面板中编辑。
4. 隐藏图层不可见、不可选中；锁定图层可见但不可编辑。
5. 页面/画布、图层、元素的 ID 全局唯一且稳定。
6. 所有持久化操作在事务中完成；失败不得留下半写入状态。
7. Undo/Redo 不跨应用重启保留；自动保存不依赖撤销历史。
8. 图书源文件和导入的附件被复制进文档，不能依赖外部路径长期存在。
9. 文本以 Markdown 源文本为唯一事实源，预览是派生结果。
10. 文档内容不得依赖在线资源才能完整显示（图片、字体、公式渲染器均需内置或降级）。

## 10. 设计基调

- **关键词**：温暖纸张、安静、专注、可靠、手感、轻微猫元素。
- **不是**：卡通猫耳贴纸、游戏化、霓虹渐变、复杂玻璃拟态、重阴影。
- **默认色**：暖白纸张、墨黑笔迹、琥珀/橘色品牌强调色；深色模式使用低亮度暖灰而非纯黑。
- **图标**：Material Symbols Rounded，统一线宽与视觉尺寸。
- **动效**：短、克制、可解释；支持系统“减少动态效果”。

## 11. 项目长期协作原则

- 这是一个长期项目，**文档优先于速度**，但文档不能成为不写代码的借口。
- 每个阶段必须有可运行、可测试的垂直切片，禁止长期维护“只有架构没有用户路径”的代码。
- 高风险能力（触控笔输入、EPUB 分页、大型画布性能、文件格式迁移）先做技术验证，再大规模依赖。
- 1.0 之前冻结核心数据模型与交互语义；之后通过版本化迁移演进。
- 用户提出的新功能先判断是否符合产品定位，再进入需求编号与路线图，不直接写代码。
