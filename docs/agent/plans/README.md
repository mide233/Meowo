# 任务计划目录

本目录存放所有实现/调研/发布计划的 Markdown 文件。**没有计划，不开始实现。**

- 阶段级计划：`phase-<n>-<slug>.md`
- 功能/任务计划：`<phase>-<area>-<slug>.md`，如 `p1-library-create-document.md`
- 调研 spike：`spike-<slug>.md`
- 发布计划：`release-<version>.md`

文件名使用小写英文与连字符；标题可以使用中文。

---

## 1. 计划状态

| 状态 | 含义 |
|---|---|
| `Draft` | 正在定义范围，尚不能实施 |
| `Ready` | 范围/验收明确，可开始 |
| `In Progress` | 正在实施 |
| `Blocked` | 等待决策/依赖/设备/用户确认 |
| `Review` | 实现完成，等待审查/验收 |
| `Completed` | 验收通过，报告已写 |
| `Cancelled` | 不再执行，需写明原因与替代 |

状态变更必须写日期与原因。`Completed` 不能只凭“代码写完”。

---

## 2. 粒度

- 一个计划对应一个可独立验收的目标；通常 0.5–5 个工作日规模。
- 大阶段先有阶段计划，再拆任务计划；阶段计划不替代任务计划。
- 跨多个模块的大功能拆成垂直切片，每片有独立验收。
- 纯文档/调研也应有计划，尤其是会影响架构/范围的调研。

---

## 3. 计划模板

```markdown
# <计划标题>

- 状态：Draft / Ready / In Progress / Blocked / Review / Completed / Cancelled
- 阶段：
- 负责人/Agent：
- 创建日期：
- 最后更新：
- 关联需求：
- 关联决策：
- 关联风险：

## 1. 目标

用可观察的结果描述“完成后用户/系统能做什么”。

## 2. 非目标

明确不在本次范围的内容，防止膨胀。

## 3. 背景与现状

现有实现、相关文件、已知限制、前置条件。

## 4. 方案

数据/接口/UI/存储/FFI 影响；关键取舍；失败路径；回滚。

## 5. 任务拆分

| # | 任务 | 产出 | 验收 | 状态 |
|---|---|---|---|---|
| 1 | ... | ... | ... | TODO |

## 6. 测试与验收

自动化命令、手工矩阵、性能/设备、格式/迁移。

## 7. 风险与依赖

风险、触发条件、缓解、需要用户确认的事项。

## 8. 进度记录

| 日期 | 状态 | 说明 |
|---|---|---|
| ... | ... | ... |

## 9. 结果

完成/未完成、证据链接、偏差、后续。
```

可以按任务裁剪章节，但目标、非目标、验收、测试、状态、结果不可省略。

---

## 4. 计划纪律

1. 开始前写；实施中更新；完成后写结果。
2. 范围变化必须记录原因与影响，不能静默扩大。
3. 发现新风险/决策需求，更新 `09`/`10` 并链接。
4. 计划不是承诺日历；不写无依据的日期承诺。
5. 不用聊天记录替代计划；不让计划停留在 `Draft` 却持续写代码。
6. 任务完成后在 `reports/` 写报告，计划链接报告。
7. 取消的计划保留，注明原因与替代方案。

---

## 5. 计划与报告的区别

- **计划**：打算做什么、为什么、怎么验收、当前进度；
- **报告**：实际做了什么、证据、偏差、遗留。

两者都必须存在。报告模板见 `../reports/README.md`。
