- 状态：Ready（许可证相关项待 OQ-001；可在不引入相关依赖的前提下先做）

## 1. 目标

在写产品功能前，验证四件决定项目成败的事：

1. Flutter + C++23 + 稳定 C ABI 能否在 Android/Windows/Linux 可靠构建、调用、测试；
2. 真实触控笔输入与渲染能否达到可用延迟，并明确跨平台差异；
3. `.meowo` 的 SQLite 格式、事务、WAL、恢复、迁移方案是否成立；
4. PDF/EPUB 图书引擎的许可证、构建、渲染与隔离路线是否可行。

同时建立最小工程骨架、CI、文档/计划/报告纪律，以及品牌/主题占位。

**Phase 0 不追求产品功能完整。**

---

## 2. 非目标

- 完整资料库、编辑器、笔迹工具、文本/图片/附件功能；
- 正式视觉设计、商店素材、发布签名；
- 云同步/账号/遥测；
- 未确认许可证的 EPUB 引擎进入发布二进制；
- 性能终极优化（只建立测量与基线）；
- 1.0 功能范围调整。

---

## 3. 前置条件

- 项目负责人确认可以初始化仓库与选择临时许可证策略；
- 可用开发机：Linux（主 CI/开发）、Windows（构建/触屏笔）、Android 设备（至少一台带主动笔的平板）；
- Flutter、CMake、Ninja、C++23 编译器、Android SDK/NDK、PDFium 构建依赖可用；
- 确认是否允许使用第三方开源依赖做 spike（不代表最终选型）；
- OQ-001/OQ-002 已知晓，spike 不擅自承诺最终交付形式。

若缺少真实笔设备，R-002/R-003/R-016 无法关闭，Phase 0 不能宣告完成。

## 7. 风险与应对

| 风险 | 触发 | 应对 |
|---|---|---|
| 无真实笔设备 | 无法测压感/掌拒 | 暂停相关结论，采购/借用设备；不得用模拟器代替 |
| C++23/NDK 工具链不兼容 | 某平台无法编译 | 降级到可用标准特性/编译器版本，记录并更新约定 |
| Flutter 事件缺失 | 拿不到 pressure/timestamp | 平台通道补充原始事件；评估自定义渲染/插件；记录限制 |
| SQLite 格式返工 | schema 不支持元素/图书 | 小步验证，保留迁移；Phase 1 前冻结核心 |
| PDFium 构建困难 | 交叉编译失败/包体过大 | 使用预编译/独立进程/替代引擎；记录许可证 |
| EPUB 无合规方案 | 许可证/成本冲突 | 升级 OQ-001，准备 PDF-only 范围变更 |
| 输入延迟不达标 | P95 > 50 ms | 分析瓶颈，调整渲染/FFI；必要时与用户确认参考设备/指标 |
| 范围膨胀 | 想顺手做功能 | 回到非目标，写入后续，不实现 |
