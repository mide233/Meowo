# 05 · 质量与测试策略

- 状态：Baseline
- 版本：v0.1.0
- 最后更新：2026-10-19
- 适用范围：Flutter UI、Dart 绑定、C++23 核心、文档格式、构建与发布

---

## 1. 质量目标

Meowo 是本地优先的写作与阅读工具。用户把长期笔记交给一个单文件，因此质量优先级如下：

1. **不丢数据、不损坏文档**；
2. **笔迹输入可靠且低延迟**；
3. **同一文档跨平台可读、外观一致**；
4. **核心流程简单、可预期、可恢复**；
5. **可访问性与本地化达到基线**；
6. **后续可维护、可迁移、可测试**。

“完成”不等于“代码能运行”。一个变更必须同时满足功能验收、自动化测试、跨平台检查和相关文档更新，才算完成。

### 1.1 质量属性与需求映射

| 属性 | 主要需求 | 验证手段 |
|---|---|---|
| 数据完整性 | `DAT-*`、`NFR-004` | 事务测试、崩溃注入、格式不变量测试、迁移测试 |
| 输入延迟 | `NFR-001` | 设备基准、帧耗时采样、手动笔测 |
| 规模与降级 | `NFR-002` | 20,000 笔迹/页、500 页基准与压力场景 |
| 启动/打开速度 | `NFR-003` | 冷启动与文档打开基准 |
| 跨平台一致 | `NFR-005` | 共享 fixture、像素容差 golden、跨平台打开测试 |
| 安全 | `NFR-007` | 不可信输入测试、fuzz、依赖更新 |
| 可访问性 | `NFR-010`、`A11Y-*` | Semantics 测试、对比度检查、手动辅助技术验收 |
| 可维护性 | `NFR-006`、`NFR-009` | 分层测试、ABI 契约测试、静态检查 |

## 2. 测试分层

### 2.1 分层总览

| 层级 | 位置 | 框架 | 运行频率 | 目的 |
|---|---|---|---|---|
| C++ 单元测试 | `packages/meowo_core/native/tests/unit` | GoogleTest + CTest | 每次提交 | 几何、笔迹、文档模型、存储、迁移、错误处理 |
| C++ 属性/模糊测试 | `packages/meowo_core/native/tests/fuzz` | libFuzzer（Clang） | 每晚/发布前 | 不崩溃、不越界、解析器健壮性 |
| FFI 契约测试 | `packages/meowo_core/test/ffi` | Dart test + C++ harness | 每次提交 | C ABI 句柄、内存所有权、错误码、生命周期 |
| Dart 单元测试 | `apps/meowo/test/unit` | `flutter_test` | 每次提交 | 控制器、状态映射、格式化、输入策略 |
| Widget / Golden | `apps/meowo/test/widget` | `flutter_test`、golden | 每次提交/PR | 关键 UI 状态、布局、主题、可访问性语义 |
| 集成测试 | `apps/meowo/integration_test` | `integration_test` | PR 合并前/每晚 | 创建、绘制、保存、重开、导入等端到端流程 |
| 手工设备矩阵 | `docs/agent/reports/` 记录 | 清单 | 里程碑/发布前 | 真实笔、触控、平台文件系统、辅助功能 |
| 性能基准 | `tools/benchmarks` | C++ benchmark + Flutter timeline | 每晚/发布前 | 延迟、帧率、内存、打开/保存耗时与回归 |

原则：

- 能用确定性单元测试验证的逻辑，不依赖 UI 或真实窗口。
- 高频几何与持久化逻辑必须在 C++ 层可独立测试，不启动 Flutter。
- UI 测试只验证用户可见行为和状态，不复制底层算法测试。
- 跨平台差异用共享 fixture 和明确的像素容差管理，不靠“看起来差不多”。
- 测试必须可重复；涉及时间、随机、文件系统、字体、GPU 的地方要注入或固定。

### 2.2 测试命名与结构

- C++：`<module>_test.cc`，测试名使用 `SuiteName.Behavior_ExpectedResult`。
- Dart：`<feature>_test.dart`，`group` 按行为分组。
- 集成：`<flow>_test.dart`，文件名表达用户任务，如 `create_draw_save_reopen_test.dart`。
- 每个回归缺陷必须新增一个在修复前失败、修复后通过的测试，或在报告中说明为何无法自动化。
- 测试数据放在 `assets/test_fixtures/` 或对应包 `test/fixtures/`，不得引用开发者个人路径。

## 3. C++ 核心测试

### 3.1 单元测试范围

必须覆盖：

- ID（UUIDv7 格式、单调性边界、解析/格式化）；
- 坐标与变换（仿射矩阵、点/矩形变换、逆变换、裁剪、旋转/翻转顺序）；
- 笔迹几何（重采样、平滑、压力映射、包围盒、命中测试、像素擦除切分）；
- 笔刷快照与压力曲线（端点、单调性、异常输入）；
- 元素/图层/页面模型（不变量、排序、可见/锁定语义）；
- 空间索引（插入、删除、查询、边界与退化矩形）；
- 撤销/重做（命令合并、内存预算、失败回滚、不可撤销操作）；
- SQLite schema、外键、CHECK、事务、WAL checkpoint、锁；
- 资产去重、引用计数、删除保护；
- 文档打开校验（版本、application_id、损坏、缺失表、未来版本）；
- 导入探测与页面计数（使用固定 fixture，不依赖网络）；
- 搜索索引（标题、文本、大小写/Unicode 归一化、删除同步）。

### 3.2 契约与属性测试

- 序列化/反序列化往返：元素 payload → bytes → payload，语义等价。
- 变换逆运算：在允许误差内恢复原点。
- 擦除不变量：擦除后所有剩余点不落入橡皮擦路径，且总几何长度不增加。
- 撤销不变量：执行命令后撤销，模型与命令前快照一致（允许规范化的 ID 顺序）。
- 页面/图层引用完整性：任何元素不能引用不存在或跨页的图层。
- 资产引用：被引用资产不能删除；删除引用后可回收。

使用固定随机种子的属性测试；失败时输出种子和最小化输入。

### 3.3 Sanitizer 与静态检查

- CI 至少运行 `-fsanitize=address,undefined` 的单元测试构建（Linux）。
- 发布前在可用平台上运行 ThreadSanitizer（或对并发模块做等价审计）。
- 启用编译警告并将项目代码警告视为错误；第三方依赖单独处理。
- 禁止未定义行为、越界读写、悬垂句柄和有符号溢出假设。
- 所有跨 C ABI 的内存所有权必须有测试和文档。

### 3.4 模糊测试

优先目标：

1. `.meowo` SQLite 打开与 schema 校验（损坏页、截断文件、恶意 schema、巨大计数）；
2. FlatBuffers 元素 payload 解析；
3. Markdown/HTML 清洗器（确保不产生脚本、远程资源、危险链接）；
4. PDF/EPUB 导入探测与图书引擎输入（在隔离进程中运行）；
5. 笔迹点序列与变换参数。

要求：

- 模糊器有超时、内存上限和输入大小上限；
- 发现崩溃/超时先转为回归用例，再修复；
- 图书引擎在子进程/沙箱中处理，超时即可终止，不能拖垮应用；
- 不允许模糊测试写真实用户目录。

## 4. FFI 契约测试

FFI 是 Dart 与 C++ 的边界，也是最容易产生生命周期错误的位置。必须测试：

- 句柄创建/销毁、重复销毁、使用已销毁句柄；
- 字符串/字节缓冲区所有权：调用方分配、被调用方分配、释放函数；
- 错误结构：错误码、消息 UTF-8、长度、空指针、截断；
- 异步任务：进度回调、取消、完成顺序、回调线程约束；
- 打开同一文档的并发请求与文件锁；
- 大 payload（接近上限的笔迹批次/资产元数据）；
- ABI 版本不匹配时的明确失败；
- Dart isolate 与 NativePort 生命周期。

规则：

- C ABI 不抛异常、不返回悬垂指针、不使用平台相关类型布局。
- 所有导出函数有 `noexcept` 语义和统一错误返回。
- ffigen 生成物不手改；ABI 头文件变更必须审查并更新契约测试。
- 每个公开函数至少有一个正常路径、一个错误路径、一个生命周期测试。
- 测试在 Linux 与 Windows 调试构建都运行；Android 通过设备/模拟器集成测试覆盖。

## 5. Dart 与 Flutter 测试

### 5.1 单元测试

覆盖：

- Riverpod 控制器状态迁移（加载、空、错误、保存中、已保存、冲突）；
- 输入策略（设备形态、笔/手指/鼠标、双指手势优先级）；
- 工具状态、撤销/重做可用性、选择集变换；
- Markdown 预览模型、链接解析、错误占位；
- 本地化 key 完整性与占位符；
- 文件导入流程的纯逻辑部分（探测结果、错误映射）；
- 保存状态机：未保存 → 保存中 → 已保存；失败必须停留在失败并给出重试。

### 5.2 Widget 测试

关键页面/组件：

- 资料库列表、空状态、搜索、排序、收藏、回收站；
- 新建文档流程（无限/书页、纸张尺寸、校验）；
- 编辑器顶栏、工具架、上下文栏、图层/页面面板；
- 文本编辑/预览切换、公式错误占位；
- 笔刷设置与压力曲线编辑器；
- 附件文件夹、删除保护提示；
- 图书导入设置、DRM/损坏错误；
- 键盘焦点顺序、Semantics、200% 字体缩放、窄屏/宽屏布局。

断言用户可见文本与语义，不依赖内部 widget 树细节。对动态内容固定字体、主题、时间和动画（`pumpAndSettle` 或显式帧）。

### 5.3 Golden 测试

- Golden 只用于稳定的视觉资产：主题令牌、工具栏、空状态、固定 fixture 文档的静态页面。
- 笔迹动态抗锯齿/GPU 差异较大，不做全页面像素 golden；改为几何/包围盒/截图容差测试，或在受控渲染器中验证。
- Golden 必须标注平台/渲染后端；更新 golden 需附截图差异说明并由 reviewer 批准。
- 文本排版受字体影响，测试使用打包的测试字体，不依赖系统字体。

### 5.4 集成测试

必须覆盖的端到端流程：

1. 离线首次启动 → 新建无极文档 → 绘制 → 自动保存 → 关闭 → 重开，笔迹/压力/图层保持；
2. 新建书页文档 → 选择纸张 → 多页 → 缩略图跳转 → 图层顺序/隐藏/锁定生效；
3. 笔迹选择/移动/复制粘贴/缩放/删除 → 撤销/重做；
4. 文本创建 → Markdown/公式渲染 → 提交为一个撤销单元 → 重开；
5. 图片导入 → 裁剪/旋转 → 保存 → 重开；
6. 附件导入 → 打开文件夹 → 被引用时删除保护；
7. PDF 导入 → 页面背景显示 → 批注 → 重开位置一致；
8. 强杀/崩溃恢复（可用测试钩子注入保存中断）→ 已完成保存内容存在，文件未损坏；
9. 损坏/未来版本文件 → 明确只读/错误，不崩溃、不覆盖；
10. 导出快照 → 在干净工作区导入 → 内容一致。

集成测试使用临时工作区，结束后清理；不得读写真实资料库。对平台文件选择器使用注入的 fake 或测试专用入口。

### 5.5 性能与帧测试

- 在 Flutter 侧使用 `IntegrationTestWidgetsFlutterBinding` 的 timeline 与自定义 trace 点记录笔迹输入到首帧。
- 延迟测量区分：事件时间戳、Dart 处理、FFI 提交、GPU 上屏；报告 P50/P95/P99 与样本数。
- 帧测试在真实设备进行，模拟器数据只作趋势参考。
- 基准结果写入 `docs/agent/reports/`，包含设备、OS、构建模式、文档 fixture、样本数。

## 6. 文档格式与迁移测试

### 6.1 格式不变量测试

每个 `.meowo` fixture 必须验证：

- SQLite `application_id` 与 `user_version` 正确；
- 必需表/索引/触发器存在，外键开启；
- 元素只能属于同页图层（复合外键）；
- 页面类型与尺寸/背景/index 的组合符合 CHECK；
- 每页最多一个 body text；
- 资产哈希唯一、引用角色合法；
- 图书源页面数与快照一致；
- 所有 blob 长度与 payload 版本可解析；
- 无悬挂引用、无孤立资产（允许显式 GC 前暂存，但打开时报告）。

### 6.2 迁移测试

- 每个 schema 版本保留一个最小 fixture 和一个完整 fixture。
- 迁移链 `vN → vN+1 → … → 当前` 必须自动化测试。
- 迁移前自动备份；迁移失败不得留下半迁移状态。
- 打开未来版本：只读或拒绝写入，绝不降级覆盖。
- 迁移后再次打开、导出、搜索、图书渲染均通过 smoke test。
- 降级/回滚策略在格式文档中记录；无法回滚时明确提示用户备份。

### 6.3 损坏与恢复测试

- 截断文件、随机字节翻转、删除 WAL、错误页大小；
- 磁盘满（用限额文件系统/注入写入失败）；
- 只读目录、权限拒绝、文件被其他进程锁定；
- 保存过程中强杀（测试钩子）；
- 备份恢复流程；
- 资产 blob 损坏时只影响该资产，不阻止打开其他内容（在可行范围内）。

验收：错误可理解、可重试/可恢复；不得静默覆盖原文件；不得把损坏文件当空文档保存。

## 7. 性能预算与基准

### 7.1 硬性目标（来自需求）

| 指标 | 目标 | 需求 |
|---|---|---|
| 笔尖到显示 P95 | < 50 ms（参考低端 Android 平板） | `NFR-001` |
| 画布交互 | 目标 60 fps；支持 120 Hz 设备不锁 60 | `NFR-001` |
| 单页笔迹 | ≥ 20,000 条流畅承载，超出优雅降级 | `NFR-002` |
| 单文档页面 | ≥ 500 个常规页面 | `NFR-002` |
| 冷启动到资料库可用 | 目标 < 3 s | `NFR-003` |
| 打开常规文档 | 目标 < 2 s | `NFR-003` |
| 大型 PDF 首屏 | 优先可用，不等待全部页面 | `NFR-003` |

### 7.2 基准场景

1. **空白画布绘制**：连续 10 秒、约 120 笔/秒输入注入，测 P50/P95/P99。
2. **20k 笔迹页面**：打开、平移/缩放、绘制新笔、擦除、选择、切换图层。
3. **500 页文档**：打开、翻页、缩略图滚动、搜索。
4. **大资产**：50 MiB 图片导入/显示；接近单资产上限的错误处理。
5. **大型 PDF**：500 页、含图像页面，首屏、翻页、批注、重开。
6. **保存**：连续绘制时自动保存不阻塞输入；保存 100 MiB 文档的耗时与内存峰值。
7. **内存**：长时间绘制/翻页后无持续增长；缓存有上限。

### 7.3 回归规则

- 每个阶段建立基线并记录硬件/构建配置。
- P95 延迟或帧时间相对基线退化 > 10% 视为阻塞，需解释、修复或由负责人批准例外。
- 性能测试不得在 debug 构建下作为发布结论；使用 profile/release。
- 优化必须以测量为依据；不得为未证实的性能猜测牺牲正确性。
- CI 跑稳定微基准；真实设备基准在里程碑执行并归档报告。

## 8. 跨平台与设备矩阵

### 8.1 自动化平台

| 平台 | 构建 | 自动化重点 |
|---|---|---|
| Linux x86_64 | Release/Debug、ASan/UBSan | C++ 全量、FFI、Flutter 集成、格式/迁移 |
| Windows x86_64 | Release/Debug | C++ 全量、FFI、文件锁/路径、Flutter 集成 |
| Android arm64 | Release/Debug | 集成测试、启动、存储、渲染、笔输入手动 |
| Android emulator | Debug | UI/流程 smoke；不用于延迟结论 |

Linux Wayland 与 X11 都需至少 smoke；Windows 高 DPI 与多显示器需手动检查。

### 8.2 真实设备手工矩阵

每个发布候选至少覆盖：

- Android 手机（无笔，手指绘制）；
- Android 平板（主动笔，压感；不同厂商至少两类）；
- Windows 触屏/手写笔二合一；
- Linux 桌面（鼠标/触控板；如可用，外接绘图板/触屏）；
- 高刷新率设备（如 120 Hz）；
- 低端/内存受限 Android 设备；
- 200% 显示缩放、系统深色模式、中文/英文界面。

记录：设备型号、OS 版本、输入设备、构建号、结果、截图/录屏、缺陷链接。

### 8.3 触控笔手工验收

必须实际用笔检查：

- 压感曲线端点与中间值；
- 掌拒：手掌落下不产生笔迹；
- 笔按钮（如支持）不误触；
- 笔尖起落、快速划线、慢速细节、悬停（如有）；
- 双指缩放/平移不打断当前笔（按规范）；
- 边缘/屏幕保护膜/不同倾斜角度下的可用性；
- 橡皮擦模式切换与笔尾橡皮（如系统映射）；
- 长时间书写发热/掉帧。

没有真实笔的自动化只能验证事件处理逻辑，不能替代本清单。

## 9. 可访问性与本地化测试

- 所有交互控件有可读 Semantics 标签、角色、状态；画布元素提供可访问的对象列表/替代操作路径。
- 键盘可完成资料库、文档创建、工具切换、保存、关闭；焦点可见且顺序合理。
- 支持 200% 字体缩放；关键按钮不裁切，文本可换行。
- 对比度符合 WCAG AA（正文/图标/焦点）；不仅依赖颜色表达状态。
- 屏幕阅读器 smoke：TalkBack（Android）、Narrator（Windows）、Orca（Linux，若可用）。
- 减少动态效果设置生效。
- 中英文所有 key 完整；无硬编码用户可见文本；日期/数字本地化；CJK 字体回退可读。
- 公式、附件、图书页提供文本替代说明（至少标题/页码/链接语义）。

---

## 10. 安全与隐私测试

- 导入恶意/畸形 PDF、EPUB、图片、Markdown；确认不执行脚本、不访问网络、不路径穿越、不解压炸弹。
- Markdown 原始 HTML 清洗；`javascript:`、`file:`、远程图片、内联事件被拒绝或安全处理。
- 附件文件名与路径规范化；压缩包/目录导入限制条目数、总大小、深度。
- 日志不含正文、笔迹、附件内容、完整路径或令牌。
- 应用默认不发起网络请求；构建产物无遥测 SDK（除非未来显式批准）。
- 依赖漏洞扫描与许可证清单在发布前审查。
- 文件权限遵循平台最小权限；Android 使用 SAF，不申请宽泛存储权限。

## 11. 测试数据与 Fixture 管理

- Fixture 分为：最小合法、完整功能、边界规模、损坏、旧版本、恶意输入。
- 每个 fixture 有生成脚本或来源说明、SHA-256、许可证/隐私确认。
- 禁止提交真实用户文档、带个人信息的 PDF、未授权字体/书籍。
- 大 fixture 使用生成脚本按需构建，避免仓库膨胀；CI 缓存需可失效。
- 随机测试固定种子；时间相关测试注入时钟。
- Golden 与基准结果和 fixture 版本绑定，fixture 变更需更新基线并说明。

## 12. CI 流水线

### 12.1 每次提交/PR

1. Markdown 文档链接/格式检查（如启用）；
2. C++ 格式化/静态检查；
3. C++ Debug 单元测试（Linux）+ ASan/UBSan；
4. Dart 格式化/分析；
5. Dart 单元 + Widget 测试；
6. FFI 契约测试（Linux）；
7. 构建 Android debug 与 Linux release（至少编译通过）；
8. Windows 构建与单元测试（可用独立 runner）。

### 12.2 合并前/每晚

- Flutter 集成测试（Linux；Android 模拟器/设备按可用性）；
- 迁移测试与格式不变量测试；
- 模糊测试短时运行；
- 性能微基准与趋势报告；
- 依赖许可证/漏洞扫描；
- 文档与需求追踪检查（新增功能是否有需求/决策/测试）。

### 12.3 发布前

- 全平台 release 构建与签名验证；
- 完整手工设备矩阵；
- 性能报告与基线对比；
- 崩溃恢复/磁盘满/权限场景；
- 可访问性手动验收；
- 许可证清单与第三方声明；
- 安装/升级/卸载/文件关联 smoke；
- 发布检查表由负责人签字。

### 12.4 CI 原则

- 失败必须可复现；flaky 测试不能长期重跑掩盖。
- 单元测试目标 < 5 分钟；超过则拆分/并行。
- 缓存依赖但不缓存测试结果。
- 不在 CI 输出用户数据或密钥。
- 构建可重复；版本号/提交号写入 about 页面与日志。

## 13. 覆盖率与缺陷管理

- C++ 核心行覆盖目标 ≥ 80%，关键模块（格式、持久化、几何、撤销）分支覆盖 ≥ 85%。
- Dart 业务逻辑行覆盖目标 ≥ 70%；UI 以关键路径覆盖为主，不追求无意义数字。
- 覆盖率下降需说明；不得用无断言测试刷覆盖率。
- 缺陷分级：
  - **S0 数据丢失/损坏/安全**：立即停止发布，修复并加回归测试；
  - **S1 核心流程不可用/崩溃**：阻塞当前阶段退出；
  - **S2 功能错误但有绕过**：发布前评估，记录；
  - **S3 视觉/文案/次要体验**：可排期。
- 已知限制必须写入文档/发布说明，不能静默存在。

- [ ] C++ 单元/契约测试通过（涉及核心时）；

- [ ] 格式/迁移变更有不变量与迁移测试；

- [ ] 无新增未处理警告、无跳过测试；
- [ ] 可访问性与本地化检查完成；
- [ ] 相关文档、计划、报告已更新；
- [ ] Reviewer 按 `08-agent-operating-protocol.md` 完成审查。
