## 6. 约束

- 遵循权威顺序与 Accepted 决策；
- 不引入未批准依赖/许可证；
- 不改变 `.meowo` schema/FFI ABI 而不更新文档与迁移；
- 不伪造保存/测试/导入成功；
- 不直接访问数据库（Flutter 侧）；
- 保持向后兼容/迁移路径（如适用）；
- 性能/内存/无障碍/本地化按规范；
- 计划、报告用 Markdown 写入 `docs/agent/`。

## 7. 实施要求

1. **先计划**：在 `{{PLAN_PATH}}` 创建/更新任务计划，包含目标、非目标、步骤、影响、测试、风险、回滚。
2. **最小垂直切片**：数据/核心 → FFI（如需要）→ Dart → UI → 测试/保存/重开。
3. **先定义失败路径**：空、错误、权限、磁盘满、损坏、取消。
4. **测试同交**：按 `05` 选择层级；核心逻辑必须有 C++ 单测；UI 关键路径有 Widget/集成测试。
5. **验证**：运行格式化、静态检查、相关测试；性能敏感变更附基准。
6. **文档同步**：更新需求/格式/UX/计划/报告（按影响）。
7. **自审**：范围、生命周期、资源、日志隐私、无障碍、无调试残留。

## 12. 停止与升级

遇到以下情况立即停止并询问：

- 需要改变 1.0 范围/格式/ABI/数据模型；
- 许可证/分发不清；
- 可能数据丢失；
- 文档冲突无法裁决；
- 关键硬件/平台不可用；
- 出现 S0/S1 缺陷；
- 任务信息缺失且影响实现。

提问：问题 → 选项 → 推荐 → 影响 → 需要用户决定的内容。
