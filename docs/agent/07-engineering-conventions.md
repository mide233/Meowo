# 07 · 工程约定

- 状态：Baseline
- 版本：v0.1.0
- 最后更新：2026-10-19
- 适用对象：所有向 Meowo 提交代码、测试、构建脚本或文档的 Agent/协作者

---

## 1. 基本原则

1. **正确性优先于技巧**：清晰、可测试、可回滚的实现优于“聪明”的捷径。
2. **边界清晰**：Flutter 负责 UI/交互/平台集成；C++ 负责文档模型、几何、存储与图书适配。
3. **单一事实来源**：需求、决策、格式、ABI 只在指定文档定义，代码不另立隐性规则。
4. **小步提交**：每个变更围绕一个可验证目标，避免巨型 PR 和跨阶段混改。
5. **数据不可逆操作必须可恢复**：迁移、导入、覆盖、删除均需备份或确认路径。
6. **不引入未批准依赖**：许可证与体积是架构问题，不是“顺手加个包”。
7. **测量后优化**：性能结论必须有基准；不为猜测牺牲可维护性。

- 测试 fixture 与生产资产分开，避免发布包误带测试数据。

## 3. C++23 约定

### 3.1 语言与工具链

- 使用 C++23；不启用 C++ 模块（Phase 0 统一决定编译器/NDK 支持后再评估）。
- 目标编译器：各平台稳定版 Clang/GCC/MSVC；Android 使用 NDK 中的 Clang。具体最低版本由 Phase 0 记录。
- 构建：CMake + Ninja（可用时）；所有平台同一套 target 语义。
- 默认开启警告；项目代码警告视为错误。第三方代码可单独豁免。
- 不使用编译器专有扩展，除非有隔离宏与回退。
- 字节序：文件格式显式小端；内存/FFI 不依赖宿主端序假设。

### 3.2 命名与格式

采用 Google C++ Style 的骨架，项目统一如下：

| 类别 | 规则 | 示例 |
|---|---|---|
| 文件 | `snake_case.cc/.h` | `stroke_geometry.cc` |
| 类型/类/结构体 | `UpperCamelCase` | `StrokePayload` |
| 函数/方法 | `snake_case` | `hit_test()` |
| 局部变量/参数 | `snake_case` | `page_index` |
| 成员变量 | `snake_case_` | `document_id_` |
| 常量 | `kUpperCamelCase` | `kMaxStrokePoints` |
| 枚举值 | `kUpperCamelCase` | `kPaged` |
| 命名空间 | 小写，项目根 `meowo` | `meowo::ink` |
| 宏 | 仅必要时 `MEOWO_UPPER_SNAKE`，尽量用 `constexpr` | — |

- 使用 `clang-format`，配置提交到仓库；不手工对齐。
- 头文件使用 `#pragma once` 或统一 include guard，二选一由 Phase 0 固定。
- include 顺序：对应头文件、C 系统、C++ 标准库、第三方、项目内部；组间空行。
- 优先前向声明减少编译依赖；公开 ABI 头文件保持自包含。
- 不用 `using namespace` 于头文件或全局作用域。
- 注释解释“为什么/约束”，不复述代码；公共 API 使用 Doxygen 风格。

### 3.3 类型与数值

- 固定宽度类型用于持久化/FFI：`int32_t`、`uint32_t`、`int64_t`、`uint64_t`。
- 尺寸/坐标使用 `double`（点单位）；像素/计数使用有符号或无符号的明确类型，避免隐式窄化。
- 禁止对浮点做精确相等比较；几何容差集中定义并测试。
- 时间使用 Unix epoch 毫秒 `int64_t`；不使用本地时区存储。
- ID 使用 UUIDv7；文本形式小写带连字符；解析失败不得静默生成新 ID。
- 金额/统计等未来字段不使用浮点。

### 3.4 错误处理

- 核心内部优先返回 `std::expected<T, Error>`；错误包含稳定 code、上下文和可本地化消息 key，而非仅字符串。
- C ABI 边界绝不抛出异常；第三方异常必须在边界捕获并转为错误。
- 不使用异常做常规控制流；资源仍用 RAII。
- `assert` 仅用于开发期不变量，不用于处理用户输入。
- 错误必须可操作：区分“用户可修复”“输入损坏”“内部错误”“资源不足”“权限/锁”。
- 禁止吞错；允许降级时必须记录并向上报告状态。
- 日志不包含用户正文/笔迹/附件内容；错误消息不泄露路径以外的隐私。

### 3.5 内存与并发

- 所有权用 `std::unique_ptr`/值语义表达；共享只读用 `std::shared_ptr<const T>`，避免循环引用。
- 不使用裸 `new/delete`；不保存指向容器元素的长期指针。
- 跨线程对象明确线程归属；共享状态用锁或消息传递，禁止数据竞争。
- 文档会话单写者模型：UI 线程不直接写 SQLite；写操作在核心工作线程执行。
- 不要在持有锁时调用回调、分配大对象或执行 I/O。
- 大资产使用流式/分块读写，避免无界内存复制。
- 每个缓存有容量/内存预算与淘汰策略。

### 3.6 性能与可读性

- 热路径避免不必要的字符串/容器复制；先测量再优化。
- 空间索引、笔迹重采样、渲染缓存属于热路径，变更必须跑基准。
- 不为了微优化引入难懂的所有权或手写 SIMD；如使用，附基准与可移植回退。
- 单函数保持可理解长度；复杂几何算法拆成可测试纯函数。

## 4. Dart / Flutter 约定

### 4.1 语言与风格

- 使用稳定版 Flutter/Dart；`flutter analyze` 零警告。
- 使用官方 `flutter_lints` 为基线，团队规则写入 `analysis_options.yaml`。
- 命名遵循 Dart 官方风格：类型 `UpperCamelCase`，变量/方法 `lowerCamelCase`，文件 `snake_case.dart`。
- 优先 `const`、`final`、不可变模型；状态变化通过明确的控制器/通知。
- 不用 `dynamic` 逃避类型；FFI 边界用生成的强类型绑定加手写安全包装。
- 用户可见字符串全部走本地化资源，不硬编码。
- 颜色、间距、圆角、字号使用主题令牌，不在 widget 中散落魔法值。

### 4.2 架构分层

```text
Widget / Page
    ↓ 只读状态、发送意图
Riverpod Controller / Notifier
    ↓ 调用领域 API
Dart domain wrapper（packages/meowo_core/lib）
    ↓ FFI
C++ core
```

规则：

- UI 不直接调用 `dart:ffi`；只依赖 `meowo_core` 暴露的 Dart API。
- 控制器不持有原生指针；句柄生命周期由 repository/session 管理。
- 文档打开/关闭成对；页面销毁必须释放会话，避免句柄泄漏。
- 异步操作必须可取消/可丢弃结果；防止旧请求覆盖新状态。
- 错误映射为领域错误类型，再转为用户提示；不把原始 C 错误码直接展示。
- 测试可注入时钟、ID、文件系统、输入事件与 FFI fake。

### 4.3 UI 与状态

- Material 3 主题；支持浅色/深色/系统。
- 所有保存状态必须真实；禁止用定时器伪造“已保存”。
- 长任务显示进度/可取消；失败提供重试与数据安全说明。
- 遵循 `04-ux-interaction-spec.md` 的输入矩阵、工具语义和响应式断点。
- 动画克制，尊重“减少动态效果”；不阻塞输入。
- Widget 拆分以职责/重建范围为依据，不按行数。
- 使用 `Semantics` 提供画布对象列表与操作替代路径；焦点顺序可预测。

### 4.4 资源与平台

- Android 使用 SAF/应用私有目录，不申请宽泛存储权限。
- Windows/Linux 路径使用平台 API，不拼接分隔符假设。
- 字体/图标资源必须确认许可证；默认使用系统字体回退，测试字体单独打包。
- 不引入 WebView 作为 Markdown/公式渲染的默认方案（D-010）。
- 平台通道只用于 Flutter 无现成能力的系统集成；业务逻辑不散落在平台代码。

## 5. FFI / C ABI 约定

1. **稳定优先**：公开头文件是 ABI 契约；新增字段/函数优先追加，不改变既有布局/语义。
2. **C 兼容**：只用固定宽度整数、指针、`const char*` + 长度、opaque handle；不使用 C++ 类型、`bool` 布局假设、异常。
3. **所有权明确**：每个返回指针必须说明由谁释放、用哪个函数释放、何时失效。
4. **字符串**：UTF-8，显式长度；不依赖 NUL 终止处理嵌入内容；空指针与零长度语义统一。
5. **句柄**：不透明、不可解引用；重复释放/使用已释放句柄必须安全失败（调试期断言 + 发布错误码）。
6. **错误**：统一错误结构/错误码；成功也可能带警告；不得只返回 `nullptr`。
7. **线程**：明确每个函数允许的线程；回调在哪个线程触发；不得在回调中调用会死锁的 API。
8. **异步**：任务有 ID、进度、取消、完成状态；取消是协作式，完成后不再回调。
9. **版本**：ABI 版本查询；Dart 侧启动时检查；不匹配给出明确错误，不尝试猜测。
10. **生成**：`ffigen` 配置与头文件提交；生成绑定不手改；手写包装层负责生命周期与类型安全。
11. **测试**：每个导出函数至少正常/错误/生命周期测试；ASan 下跑 FFI 测试。
12. **禁止**：跨 ABI 传 STL 容器、Dart 回调持有原生栈引用、在 C++ 长期保存 Dart 临时指针。

详细架构见 [02-technical-architecture.md](02-technical-architecture.md)。

## 6. SQLite、格式与迁移

- `.meowo` 的 schema 以 [03-document-format.md](03-document-format.md) 为唯一权威。
- 所有连接：`foreign_keys=ON`、WAL、明确的 busy timeout；不使用默认隐式行为。
- 每个文档会话一个写连接；读操作可在受控连接上并行；跨进程用文件锁 + SQLite 锁双保险。
- 所有 SQL 使用预编译语句/参数绑定；禁止字符串拼接用户输入。
- 事务边界由用例定义；UI 操作不直接开启长事务；批量导入分块提交。
- schema 变更必须：递增 `user_version`、提供前向迁移、备份、迁移测试、失败回滚。
- 不删除/重命名历史迁移；不修改已发布迁移脚本。
- 派生数据（缩略图、搜索索引、图书缓存）不作为事实来源，可重建。
- 资产以内容哈希去重；删除前检查引用；GC 必须可中断/可恢复。
- 大 blob 写入避免一次性复制；设置单资产与文档大小上限并在导入前检查。
- 打开外来文件先校验 `application_id`/版本/完整性，再决定只读或拒绝。
- 导出使用一致性快照，不复制活动 WAL 文件。
- schema/FlatBuffers 变更附带格式不变量测试与跨版本 fixture。

## 7. 测试约定

- 测试与实现同一提交；修复缺陷先写失败测试或记录无法自动化的原因。
- C++：GoogleTest + CTest；测试文件与模块对应；不依赖网络/真实用户目录。
- Dart：`flutter_test`；Widget 测试用 fake repository，不启动真实 C++。
- FFI：真实核心 + 临时工作区；覆盖句柄/错误/取消/大 payload。
- 集成：`integration_test`，使用临时工作区；关键路径必须自动化或进入手工矩阵。
- 测试命名表达行为与预期，不写 `test1`。
- 时间、随机、文件系统、字体、网络（若未来）必须可注入/固定。
- 不提交 `skip` 测试；临时跳过需链接问题并在报告中记录。
- 性能测试使用 release/profile，并记录设备与构建号。
- 覆盖率目标与发布门槛见 [05-quality-and-test-strategy.md](05-quality-and-test-strategy.md)。

## 8. 依赖与许可证

### 8.1 引入依赖前

必须回答：

1. 是否真的需要？标准库/现有模块能否解决？
2. 许可证是什么？是否允许当前分发模式？
3. 维护状态、最近发布、已知漏洞？
4. 支持哪些平台/架构？Android NDK/Windows/Linux 是否可用？
5. 体积/内存/启动成本？
6. 能否隔离/替换？是否需要暴露到 C ABI？

### 8.2 许可证规则

- 允许（需记录）：MIT、BSD-2/3、Apache-2.0、ISC、Zlib、Unlicense 等宽松许可证。
- 需法务/负责人审查：MPL-2.0、LGPL、带专利/广告条款的许可证。
- **禁止**在 OQ-001 明确批准前引入 AGPL/GPL 依赖到主线或发布二进制。
- 禁止未知许可证、无许可证、来源不明的二进制/字体/模型。
- 每个第三方依赖记录：名称、版本、许可证、用途、平台、体积、升级策略。
- 交付物包含所需版权声明/许可证文本。
- 安全更新优先；升级需跑契约/格式/集成测试。

### 8.3 版本管理

- 使用锁文件/固定版本；不使用“latest”。
- 不在同一次变更中无理由升级多个大依赖。
- 生成代码与工具版本记录在 README/工具配置。
- 不 fork 上游除非必要；fork 必须记录原因、补丁与同步策略。

## 9. Git 与评审

### 9.1 分支与提交

- 主分支保持可构建；功能分支从最新主分支创建。
- 分支名：`feat/<short-slug>`、`fix/<short-slug>`、`docs/<short-slug>`、`chore/<short-slug>`。
- 使用 Conventional Commits：

```text
feat(editor): add pressure curve editor
fix(core): prevent asset deletion while referenced
docs(agent): clarify body text overflow
test(core): cover pixel erase splitting
refactor(ffi): isolate session handle table
chore(ci): add windows unit tests
```

- 一个提交一个逻辑变更；格式化与行为变更尽量分开。
- 提交信息说明“为什么”，不复制 diff。
- 不提交密钥、令牌、个人路径、真实用户内容、构建产物。
- 不强制 amend 已共享历史；不 force-push 主分支。

### 9.2 PR/变更说明

必须包含：

- 关联需求 ID / 决策 ID / 计划任务；
- 变更摘要与不在范围内的内容；
- 测试证据（命令、结果、设备）；
- 格式/ABI/迁移影响；
- 截图/录屏（UI 变更）；
- 风险与回滚方式；
- 文档更新清单。

### 9.3 评审重点

1. 数据安全与错误路径；
2. 边界条件、并发、生命周期；
3. 是否符合需求/决策，而不是“看起来能用”；
4. 测试是否真的验证行为；
5. 性能敏感路径是否有基准；
6. 可访问性/本地化；
7. 依赖/许可证；
8. 文档是否同步。

评审不通过时，不以“后续再修”合并核心数据路径变更。

## 10. 构建、命令与 CI

Phase 0 将固定脚本；在此之前使用以下约定名称，避免各 Agent 自创命令：

```bash
# 仓库根目录
flutter pub get
flutter analyze
flutter test

# C++ 核心
cmake -S packages/meowo_core/native -B build/native -G Ninja -DCMAKE_BUILD_TYPE=Debug
cmake --build build/native
ctest --test-dir build/native --output-on-failure

# FFI 绑定生成（示例，最终以 tools/ 脚本为准）
dart run ffigen --config packages/meowo_core/ffigen.yaml

# 集成测试（设备/桌面按平台）
flutter test integration_test
```

规则：

- 命令必须可在干净环境重复执行；文档记录前置依赖。
- 构建脚本不接受隐式本机路径；使用环境变量/配置。
- CI 与本地使用同一套格式化/测试入口。
- 不把“手动执行某 IDE 操作”作为唯一构建步骤。
- 构建输出目录统一在 `build/` 或工具约定目录，并加入忽略。

## 11. 文档纪律

- 所有 Agent 文档、计划、报告在 `docs/agent/`，Markdown。
- 改需求/决策/格式/ABI/UX/测试门槛 → 同一次变更更新对应文档。
- 决策不删除，使用 `Superseded` 链接新决策。
- 计划真实更新状态，不做事后补写的“完美计划”。
- 报告包含证据，不只写“已完成”。
- 文档链接使用相对路径；标题层级稳定，便于检索。
- 技术名词首次出现给中文解释；用户界面文案不写入文档作为最终翻译，需走本地化资源。
- 文档中的示例不得包含真实隐私数据。

## 12. 安全与隐私

- 所有导入文件视为不可信：限制大小/页数/解压比/嵌套深度；在隔离进程处理高风险引擎。
- 禁止执行 PDF/EPUB/Markdown 中的脚本、表单提交、远程资源。
- 路径规范化，拒绝 `..`、绝对路径注入、符号链接逃逸。
- 日志默认不含正文、笔迹、附件内容、完整路径；诊断包需用户明确导出。
- 不引入遥测/联网 SDK；未来若加入必须显式同意并更新隐私文档。
- 依赖漏洞扫描与安全更新纳入发布检查。
- Android 遵循 scoped storage/SAF；桌面遵循用户目录权限。
- 崩溃报告（若未来加入）必须可选、脱敏。

## 13. Definition of Done（工程视角）

一个变更只有在以下全部成立时才算完成：

- [ ] 关联需求/决策/计划任务明确；
- [ ] 实现遵循分层与命名约定；
- [ ] 单元/契约/Widget/集成测试按影响范围补齐并通过；
- [ ] 错误路径、空状态、权限/磁盘满/损坏输入已考虑；
- [ ] 格式/ABI/schema 变更附迁移与兼容性测试；
- [ ] 性能敏感变更附基准或说明为何不受影响；
- [ ] 无新增 analyzer/compiler 警告，无跳过测试；
- [ ] 可访问性与本地化符合要求；
- [ ] 依赖/许可证已记录；
- [ ] 文档、计划、报告已更新；
- [ ] 代码已自审，PR 描述含测试证据与风险；
- [ ] 不包含无关重构/格式化噪音。

## 14. 版本与发布

- 应用版本遵循 SemVer；构建号单调递增。
- 文档版本独立于应用版本；格式 `user_version` 独立递增。
- 1.0 前允许 breaking 变更，但必须迁移/备份；1.0 后格式与 ABI 遵循兼容策略。
- 发布说明包含：新功能、修复、已知限制、格式/迁移影响、许可证变更。
- 不发布带未解决 S0/S1 缺陷的构建。
- 发布产物可追溯到提交号与 CI 构建号。
