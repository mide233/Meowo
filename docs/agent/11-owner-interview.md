## 0. 使用方式

### 0.1 回答格式

直接按编号回答即可，例如：

```text
Q-001: B（闭源商业，考虑购买 MuPDF 授权）
Q-003: Google Play + Windows 安装包 + Linux Flatpak
Q-004: 暂无硬截止；先做 Phase 0
Q-013: 1.0 不需要同步
```

如果一整组都接受建议，可以写：

```text
Q-001 到 Q-010 按建议，除了 Q-004 不设日期
```

如果不知道，写“不知道/需要 spike”，不要为了让问卷完整而猜。未回答项不会自动变成承诺。

### 0.2 优先级

| 优先级 | 含义 | 处理 |
|---|---|---|
| `P0` | 不回答就无法开始 Phase 0，或会改变许可证/架构/首发范围 | 现在回答 |
| `P1` | 进入对应功能阶段前必须回答 | 可在 Phase 0 期间回答 |
| `P2` | 可先采用基线默认，后续确认 | 不阻塞开工 |

以下问题不是重复，而是要求你明确：**如果这些假设不成立，现在就要改，而不是做到一半才发现。**

1. **为什么一定要 Flutter + C++23？** 如果纯 Dart/Flutter 能完成 1.0，是否愿意放弃 C++ 核心以降低构建、FFI、调试和招聘成本？反过来，如果 C++ 是硬要求，谁维护三平台工具链？
2. **为什么文档必须是单文件 SQLite？** 大量图片/PDF 会让单文件达到数 GB；备份、云盘、分享、损坏恢复是否可接受？是否考虑“数据库+资产目录”的包格式？
3. **为什么书页只能单页视图？** 用户是否期待连续滚动/双页？如果这是刚需，是否愿意用性能复杂度换取体验？
4. **为什么文档类型和纸张尺寸不可变？** 用户创建后想改 A4→A5、书页→无极时怎么办？是否接受“新建并复制内容”的替代流程？
5. **为什么不做 WYSIWYG？** 目标用户是否能接受 Markdown 源码？如果目标用户是普通笔记用户，这是否是致命体验差异？
6. **为什么 1.0 不做同步/导出？** 用户如何备份、换机、分享、打印？只给 `.meowo` 是否足够形成完整产品闭环？
7. **为什么搜索不覆盖手写？** 手写笔记的用户是否认为“搜索不到”不可接受？如果是，OCR 是否应提前？
8. **为什么不做文件夹/标签？** 文档多了以后，收藏+搜索是否真的够？是否会出现“资料库很快变乱”的问题？
9. **为什么书籍不能插入空白页/笔记页？** 用户读 PDF 时想加一页总结，是否只能另建文档？这是否违背“阅读即书写”？
10. **为什么 EPUB 要固定快照？** 用户是否期待重排、字体调整、夜间模式、复制文本？固定快照是否让“阅读器”退化为“图片批注器”？
11. **为什么不做加密？** 如果用户保存隐私/工作文档，设备丢失时怎么办？是否接受“1.0 不承诺隐私安全”？
12. **为什么不允许跨文档复制？** 用户整理笔记时是否经常需要把一页内容搬到另一文档？内部剪贴板限制是否会显得残缺？
13. **为什么只支持 PNG/JPEG/WebP？** 用户从手机/网页/截图粘贴 HEIC/GIF/SVG 时如何处理？是否会频繁遇到“格式不支持”？
14. **为什么测试只谈覆盖率和自动化？** 没有真实手写笔、真实 PDF/EPUB 样本、低端设备，如何证明“优秀”？
15. **为什么现在就要锁死 1.0 范围？** 如果 Phase 0 发现 PDFium/EPUB/Flutter 手写不可行，是否允许调整范围？谁批准？
