## 0. 使用方式

本文档采用轻量 ADR（Architecture Decision Record）形式。

状态含义：

- `Accepted`：当前基线决策，Agent 可以据此实现。
- `Proposed`：推荐方案，尚待负责人确认；在确认前不得作为不可逆承诺。
- `Superseded`：已被新决策取代，保留历史。
- `Open`：待确认，可能阻塞某个阶段。
- `Rejected`：已考虑但明确不采用。

规则：

- 任何改变文件格式、FFI ABI、模块边界、1.0 范围的决策，必须新增记录或更新状态。
- 不能删除 `Superseded` 记录，需注明取代它的决策 ID。
- Agent 发现需求与决策冲突时，停止有争议的实现，先记录到本文档。

## 1. 已接受的基线决策

### D-001 · 本地优先，1.0 无账号与云同步

- 状态：`Accepted`（1.0 范围）
- 决策：全部 1.0 功能离线可用；不引入账号、云同步、遥测、在线依赖。文档、附件、图书源均本地自包含。
- 理由：降低复杂度、保护隐私、符合个人笔记的核心价值；先打磨单机体验，再考虑同步。
- 影响：`APP-001`、`DAT-014`、`NFR-008`；同步需求放入 1.0 后候选。
- 未来扩展：稳定 ID、事务性文件格式、版本化 schema 为同步保留基础，但 1.0 不实现冲突合并。

### D-002 · Flutter UI + C++23 核心 + Dart FFI

- 状态：`Accepted`
- 决策：
  - Flutter 负责 UI、文本编辑、画布显示与平台集成；
  - C++23 核心负责文档模型、SQLite 持久化、笔迹几何、命中测试、空间索引、撤销栈、图书引擎适配；
  - 通过稳定 C ABI 暴露给 Dart，使用 `ffigen` 生成绑定；
  - C++ 核心可独立构建和测试，不依赖 Flutter。
- 理由：UI 开发效率与跨平台一致性由 Flutter 提供；高频几何、文件格式和性能敏感逻辑由 C++ 掌控。
- 约束：C++ 不得直接依赖 Flutter 类型；Flutter 不得直接打开文档数据库；见 [02-technical-architecture.md](02-technical-architecture.md)。
- 影响：全部实现阶段。

### D-003 · `.meowo` 是单文件 SQLite 数据库

- 状态：`Accepted`
- 决策：文档以单个 SQLite 3 数据库文件存储，扩展名 `.meowo`；WAL 模式；所有内容（含图片、附件、PDF/EPUB 源）内嵌。
- 理由：事务/崩溃恢复成熟，增量写入、查询和迁移便利，单文件便于携带。
- 约束：
  - 使用自定义 `application_id` 与 `user_version` 标识；
  - 分享/导出必须使用一致性快照，不复制活动 WAL 中间态；
  - 详情见 [03-document-format.md](03-document-format.md)。
- 影响：`DAT-001`–`DAT-015`。

### D-004 · 文档类型创建时确定，不提供类型转换

- 状态：`Accepted`（1.0）
- 决策：无极喵文档与书页喵文档创建时确定；1.0 不实现互相转换。导入 PDF/EPUB 只生成书页类型（喵书籍）。
- 理由：两种坐标/页面模型差异大，转换会引入内容映射、裁剪和撤销语义；先保证各自体验完整。
- 影响：`DOC-001`、`DOC-009`；未来若支持转换需专门设计。

### D-005 · 书页文档 1.0 使用单页视图 + 缩略图导航

- 状态：`Accepted`（1.0）
- 决策：一次显示一页，支持翻页/跳转/缩略图；不实现连续纵向长卷或双页视图。
- 理由：与图书阅读、页面图层模型一致，减少复杂滚动命中与性能问题；无限画布已覆盖连续工作需求。
- 影响：`CAN-007`；连续视图列为 1.0 后候选。

### D-006 · 用户页面纸张尺寸为文档级统一设置

- 状态：`Accepted`（1.0）
- 决策：新建书页文档时选择 A4/A5/B5/Letter/Legal/自定义与方向；同一文档所有用户页面统一。1.0 创建后不修改。
- 理由：避免改变纸张尺寸后元素裁切/重排的完整性问题；喵书籍页面由源文件决定。
- 影响：`DOC-002`、`DOC-003`、`DOC-008`。

### D-007 · 图书页结构不可编辑，批注叠加

- 状态：`Superseded`（源页规则仍有效；插入笔记页部分被 D-022 取代）
- 决策：喵书籍的源页面不可新增/删除/重排；源内容只读；所有批注为普通元素，位于页面图层。
- 理由：保持源页面索引与标注锚点稳定；EPUB 分页重排会使已有标注错位。
- 影响：`BOOK-006`、`BOOK-014`；插入 Meowo 笔记页的规则见 D-022。

### D-008 · 图层按页管理，图书/纸张背景在图层之外

- 状态：`Accepted`
- 决策：
  - 每个书页/无极画布独立图层栈；
  - 纸张背景和图书页背景不属于可编辑图层；
  - 所有用户元素必须属于一个图层；
  - 渲染顺序：纸张 → 图书页背景 → 图层从下到上 → 层内元素从后到前。
- 理由：概念清晰，隐藏/锁定与选择语义稳定。
- 影响：`LYR-001`–`LYR-010`。

### D-009 · 画布本底文本是特殊文本元素，不是独立文档类型

- 状态：`Accepted`（1.0）
- 决策：
  - 书页文档：本底文本占页面正文区域，默认可放在最底图层；
  - 无极文档：锚定文档原点、固定阅读宽度、纵向自动增长；
  - 它不是“自动跨页排版引擎”，超出页面时遵循文本溢出规则；
  - 文本仍以 Markdown 为事实源，可被选择、移动和放入图层。
- 理由：复用文本与图层模型，不引入文档级富文本排版系统。
- 影响：`TXT-004`、`TXT-013`；文本溢出 UX 见 OQ-004。

### D-010 · Markdown 源码编辑 + 渲染预览，Math 使用 KaTeX 兼容渲染

- 状态：`Accepted`（1.0；Q-085 确认；OQ-003 关闭）
- 决策：
  - Markdown 为唯一事实源；
  - 1.0 提供源码编辑 + 实时/可切换预览，桌面可并排、移动端切换；
  - 不做完整所见即所得 Markdown 编辑器；
  - 数学公式采用 KaTeX 兼容语义，使用本地 Flutter 渲染器，避免 WebView；
  - 具体支持边界见 `TXT-001`/`TXT-002`/`TXT-012`。
- 理由：完整 CommonMark/GFM 的所见即所得编辑是极高复杂度项目；先保证内容正确、可编辑、可移植。
- 后果：文本输入体验更像“带预览的 Markdown 编辑器”，不是 Notion 式块编辑器。若产品必须 WYSIWYG，需要单独立项并推迟文本阶段。
- 影响：`TXT-001`–`TXT-016`；OQ-003。

### D-011 · 图书引擎通过抽象接口隔离，PDF 默认 PDFium

- 状态：`Superseded`（由 D-020 取代）
- 决策：
  - 业务层只依赖 `BookEngine` 抽象；
  - PDF 使用 PDFium（BSD 类宽松许可证）作为默认候选；
  - EPUB 引擎在许可证与能力确认前不合并进主线二进制；
  - 引擎必须支持取消、按页渲染、页数/尺寸/目录查询。
- 理由：避免 PDF/EPUB 具体库污染核心；可替换、可测试；优先控制许可证风险。
- 影响：`BOOK-001`–`BOOK-016`；OQ-001 必须在 Phase 0 关闭。

### D-012 · 撤销分为画布全局历史与文本局部历史

- 状态：`Accepted`（1.0）
- 决策：
  - 画布/对象操作（绘制、擦除、变换、图层、页面结构）进入全局撤销栈；
  - 文本编辑内部使用文本控件撤销栈；
  - 退出文本编辑或提交时，整个文本变更为一个全局撤销单元；
  - 撤销历史不跨应用重启保存。
- 理由：避免文本输入每个字符进入画布历史；符合用户对不同编辑上下文的预期。
- 影响：`SEL-009`、`TXT-015`、`DAT-004`。

### D-013 · 1.0 只提供文档复制/快照导出，不做多格式导出

- 状态：`Superseded`（由 D-021 取代）
- 决策：`LIB-008` 的导出为 `.meowo` 自包含副本；PDF/PNG 导出、打印、第三方格式转换列入 1.0 后候选。
- 理由：先保证内容所有权与备份闭环，不引入导出保真度的额外项目。
- 影响：`DAT-007`、`LIB-008`；用户如需要打印/PDF 输出需确认调整范围。

### D-014 · 1.0 图片格式为 PNG/JPEG/WebP

- 状态：`Accepted`
- 决策：至少支持三种格式；SVG/动画 GIF/HEIC 不作 1.0 承诺。
- 理由：跨平台解码一致性与测试可控性。
- 影响：`IMG-001`、`NFR-005`；系统剪贴板若只产生其他格式则先转换，失败给提示。

### D-015 · 手指绘制默认值按设备形态设定

- 状态：`Accepted`（Q-128 确认；所有平台提供“手指可绘制”开关）
- 决策：
  - 手机（宽度 < 600 dp）：默认允许单指绘制，双指平移/缩放；
  - 平板/桌面：默认笔绘制，单指平移/双指缩放；可通过设置或画布快捷开关启用手指绘制；
  - 任何模式下，双指手势优先于绘制（文本编辑区域除外）。
- 理由：手机通常无笔；平板误触成本高。仍提供无笔设备启用手指绘制的入口。
- 影响：`INP-003`、`INP-004`；具体矩阵见 UX 规范。
- 风险：设备形态不是输入能力的可靠代理；若 Phase 0 的输入验证表明需要按“最近是否检测到笔”自动切换，则更新本决策。

### D-016 · 1.0 全文搜索只覆盖标题与文本，不覆盖手写

- 状态：`Accepted`
- 决策：搜索标题 + 文本元素纯文本内容，不声称手写可搜索；不引入 OCR。
- 理由：OCR 是独立的大型能力，1.0 不承诺错误率与语言覆盖。
- 影响：`LIB-006`、`LIB-011`。

### D-017 · 应用内部剪贴板不跨文档复制资产

- 状态：`Superseded`（由 D-023 取代）
- 决策：画布元素复制/粘贴支持同一文档跨页（条件允许）与图层；跨文档粘贴不在 1.0 必须范围。文本通过系统剪贴板正常复制。
- 理由：跨文档复制涉及资产引用复制/去重和 ID 重新映射，先降低风险。
- 影响：`SEL-007`；未来可升级为带资产复制的跨文档剪贴板。

### D-018 · 所有 Agent 文档、计划和报告使用 Markdown 并存放在 `docs/agent/`

- 状态：`Accepted`
- 决策：不接受仅在对话中存在的计划；任务计划必须在 `docs/agent/plans/`，调研报告在 `docs/agent/reports/`。
- 理由：用户明确要求，也便于后续 Agent 接手。
- 影响：`08-agent-operating-protocol.md`。

### D-020 · PDF/EPUB 统一使用 MuPDF，接受 AGPL

### D-021 · 1.0 导出 `.meowo`/PDF/PNG 包/选中页 PNG，不做系统打印

### D-022 · 书籍允许在源页之间插入 Meowo 笔记页

- 状态：`Accepted`（部分取代 D-007；Q-043/Q-043b）
- 决策：源页只读、不可重排/删除；笔记页可插入/删除/重排，同纸张尺寸、空白背景、完整图层能力；导出按当前页序。

### D-023 · 支持跨文档复制，深拷贝资产并重写链接

- 状态：`Accepted`（取代 D-017；Q-061/Q-061b）

### D-024 · 单窗口 + 标签页，重启恢复最近标签

- 状态：`Accepted`（Q-030/Q-030b/Q-046）
- 决策：单应用窗口、多文档标签；同一文档最多一个编辑标签；再次打开聚焦已有标签；重启恢复标签列表，不恢复未保存临时状态。
- 影响：`04`、会话持久化、文件锁。

### D-025 · Android 手机提供完整编辑

- 状态：`Accepted`（Q-011b/Q-024/Q-138）
- 决策：手机竖屏/横屏均支持图层、套索、书页/无极画布、文本等完整编辑；不做系统分屏/多窗口。
- 影响：响应式布局、工具栏、触控目标与测试矩阵；显著增加范围。

### D-026 · 无障碍验收降级为自动化扫描

- 状态：`Accepted`（Q-146/Q-146b；约束 Q-016/Q-134）
- 决策：1.0 只保证自动化扫描通过；不承诺完整屏幕阅读器/纯键盘操作；保留基础字体缩放（至少 200% 不破版）、高对比度、减少动画、色盲友好 UI；画布不做逐笔朗读。
- 影响：`04`、`05`、发布说明；此前 Q-016/Q-134 的完整承诺撤回或标记未验证。

### D-027 · 单附件上限 512 MiB

- 状态：`Accepted`（Q-093；修正 Q-012）
- 决策：任意文件类型可嵌入；单附件 ≤512 MiB；单文档建议 ≤16 GiB；>100 MiB 警告；超出限制拒绝并说明原因。
- 影响：`03` 资产限额、导入校验、UI 提示。

### D-028 · 活动资料库存储位置

- 状态：`Accepted`（Q-115/Q-115b；约束 Q-019）
- 决策：Android 活动资料库在应用私有目录，SAF 仅导入/导出；桌面默认系统应用数据目录，支持用户选择资料库目录；云盘/同步文件夹不作为活动库。
- 影响：`03` workspace 布局、文件锁、权限、备份说明。

### D-029 · 搜索范围与中文检索

- 状态：`Accepted`（Q-124/Q-125/Q-125b；D-016 仍有效）
- 决策：搜索标题、文本元素、书籍可提取文本层、附件文件名；不搜索手写、不做 OCR；中文采用 FTS5 trigram + 1–2 字 LIKE/前缀回退；索引可重建；结果带上下文/高亮。
- 影响：`LIB-*`、`03` 缓存、`05` 搜索测试。

### D-030 · 1.0 性能门槛

- 状态：`Accepted`（Q-143；取代/补充 `05` 的旧门槛）
- 决策：P95 <50 ms；20k 笔迹/页；500 页；冷启动 <3 s；打开标准文档 <2 s；翻页 P95 <150 ms；Android 峰值 <1 GB；桌面峰值 <2 GB；APK <150 MB；桌面安装包 <200 MB。Phase 0 后只能收紧。
- 影响：`05`、CI 基准、发布门禁。

### D-031 · Markdown 文件导入生成可编辑书页文档

- 状态：`Accepted`（Q-015/Q-015b/Q-087；关闭 OQ-002 的 B 部分）
- 决策：`.md` 导入生成可编辑书页文档，正文为 `page_body`；相对图片内嵌；缺失图片占位；不回写 `.md`；不做只读 Markdown 书籍。
- 影响：`INP-*`、`TXT-*`、分页规则（OQ-013）。

### D-032 · 工作区独占锁（Alpha.5 实现）

- 状态：`Accepted`（Alpha 临时策略；Q-120 的只读第二实例尚未实现）
- 决策：工作区打开时对 `<workspace>/.meowo.lock` 获取非阻塞 `flock(LOCK_EX|LOCK_NB)`，持有到工作区关闭；第二个实例直接拒绝并返回“资料库已被另一个 Meowo 实例打开”。数据库先关闭、再释放锁。
- 影响：`03` 文件锁、`12` 第二实例语义、启动错误 UX；与 Q-120 的“只读视图 + 另存副本”存在已知偏差，发布前必须补齐或明确降级。
- 验证：`Core.RejectsConcurrentWorkspaceOpen` 覆盖首开成功、二次拒绝、关闭后可重开。

### OQ-001 · 许可证与 EPUB 引擎路线（阻塞 Phase 4，但必须 Phase 0 决策）

**问题**：项目是否接受 GPL/AGPL 类 copyleft 许可证？是否计划闭源或商业分发？

影响：EPUB 固定分页是 1.0 需求。可快速获得成熟能力的引擎（如 MuPDF）通常使用 AGPL 或商业授权；宽松许可证方案需要自研 HTML/CSS 分页或寻找其他库，周期与风险显著增加。

选项：

| 选项 | 优点 | 代价 |
|---|---|---|
| A. 项目采用 GPLv3/AGPL 兼容开源许可，使用 MuPDF（AGPL）处理 EPUB/PDF | 最快获得成熟 EPUB/PDF 分页、渲染、目录；功能覆盖好 | 整个应用需遵循 copyleft；闭源商业化受限；AGPL 义务需法律审阅 |
| B. 项目保持宽松许可证，PDF 用 PDFium，EPUB 自研/第三方宽松引擎 | 商业化自由 | EPUB 开发周期长，复杂 CSS/分页保真度风险高 |
| C. 购买 MuPDF 商业授权 | 同时获得能力与闭源自由 | 成本；需评估预算与授权范围 |
| D. 1.0 暂缓 EPUB，仅支持 PDF | 快速交付核心 | 不满足当前 1.0 需求，需要用户明确缩减范围 |

**推荐**：若这是开源、非商业项目，Phase 0 用选项 A 做技术验证并记录许可证影响；若有闭源/商业计划，选 C 或 B，不先接 AGPL 依赖。

**负责人**：项目负责人  
**截止**：Phase 0 结束前  
**临时默认**：PDFium 做 PDF 适配器；EPUB 引擎保持接口与假实现，不进入发布二进制。

### OQ-002 · “MD 阅读”的范围（阻塞文本/导入阶段的范围确认）

**问题**：产品描述中的 Markdown 阅读，具体指：

- A. 笔记内部文本元素可渲染/阅读 Markdown（当前基线已覆盖）；
- B. 必须支持打开/导入独立 `.md` 文件；
- C. 必须像 PDF 一样将 `.md` 作为只读“书页背景”分页阅读并批注；
- D. 必须支持 `.md` 导入后编辑并保存回 Markdown。

当前基线：A 必须；B/C/D 未承诺。若需要 B/C/D，需增加需求、文件和分页策略。

**推荐**：1.0 先实现 A；B 以“导入为新的书页文档正文文本”实现（不保证自动分页）；C/D 放入后续，避免同时为 Markdown 做第二套分页引擎。

**负责人**：项目负责人  
**截止**：Phase 3 设计前

### OQ-003 · 文本编辑必须所见即所得吗？

**问题**：1.0 是否接受 Markdown 源码编辑 + 预览，还是从第一天就必须像 Typora/Notion 一样内联所见即所得？

当前基线：D-010 选择源码 + 预览。

影响：WYSIWYG 会显著增加解析/编辑/IME/撤销/光标映射复杂度，可能占据整个 Phase 3 以上。

**推荐**：1.0 接受源码 + 预览；完成后根据用户反馈决定是否在 1.x 增加块级 WYSIWYG。

**负责人**：项目负责人  
**截止**：Phase 3 开始前

### OQ-004 · 书页本底文本溢出页面时如何处理？

**问题**：书页文档的“画布本底文本”内容超过一页时，1.0 允许哪种行为？

选项：

- A. 固定页面区域，编辑时可滚动，非编辑时显示“有内容溢出”提示，由用户拆页（当前基线，最稳）；
- B. 自动续排到下一页（需要文档级文本流与页面锚定，复杂度高）；
- C. 本底文本仅在无极文档可用，书页文档只允许文本框（偏离用户最初需求）。

**推荐**：A。若用户需要自动续排，需要作为独立“流式文本”项目，而不是偷偷夹带。

**负责人**：项目负责人  
**截止**：Phase 3 开始前
